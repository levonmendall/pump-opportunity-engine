# Candidate audit and capture reason retention

Frozen source `d1999faeaa3b42d57cc890359e1a01e8e80c1d20`, based on installed69. This is prospective source diagnostics, not a reconstruction of unknown historical causes or an installed validation result.

The complete path was mapped before implementation:

1. `native-flow-audit.ts` returns exact audit status/reason. `NativeAuditSession` preserves logical session errors and late diagnostic outcomes. `NativeCandidateRunner` records these, quality gaps and decision expiry, including coalesced local dispatch state.
2. `NativeCandidateRunner.status().decisions` and its adaptive counterpart contain admitted predictive assessments, not these failed outcomes. Candidate retirement deletes the bounded dispatch trace; WATCH rows retain only their latest transition reason.
3. `nativeCandidateReportingProjection` and `nativePaperObservationReporting` already preserve nested `watch.summary` facts. The final source snapshot passes that summary to the original operating projector. Aggregate failures are exposed, while the specific retired failure reasons were absent.

The runner now retains a fixed allowlist of reason codes, per-kind/reason occurrence counters and the latest eight sanitized outcomes in `status.watch.summary.auditDiagnostics`. Scope is explicitly **CURRENT_RUNNER_INSTANCE**, with its original start time. Existing retained aggregate counters and qualification evidence remain unchanged. Unknown reasons use `OTHER_UNEXPORTED_REASON`; raw provider errors, credentials, URLs, paths, signatures and payloads are never copied. Original event timestamps, target/deadline and last matching target's dispatch state/action are retained where known. No deadline is invented for a gap without a target. Dynamic WebSocket close and node-error codes retain only bounded numeric details.

The original public projection emits one existing bounded note containing the most frequent reason occurrences and latest outcome. A deadline miss remains a deadline outcome, not an inferred provider timeout. Failed audits can produce both an audit outcome and a subsequent quality gap; the counters are therefore labeled occurrences, not unique windows or incidents. No diagnostic decisions are inserted, and financial decision rows remain untouched. At the existing ten-note limit, only the optional RPC-call summary yields to financial history, completed protection, held strategies and source failures. No new strict public schema or frontend change is required.

No scheduling, retries, requests, timeouts, qualification rules, source admission, financial gates, ledger, recording priority or service control changed. The diagnostic state has no timer, provider or I/O. Normal warming windows and valid strategy rejections are not reclassified as failures. Prior-run causes remain unknown rather than being assigned new reasons.
