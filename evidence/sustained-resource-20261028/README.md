# Sustained resource telemetry for the next combined forward interval

Implemented and verified offline on top of lead `0395349`. Not dispatched or measured on EC2. The existing independent supervisor now records a private, bounded `resource-samples-<segment>.ndjson` every 15 seconds while the source runs. It does not add a financial writer, provider request, profiler, queue, or process. All existing source/publisher safety limits and management recovery rules remain unchanged.

Each sample binds the reviewed executable, original experimental account/inception, segment and known run. It records own-UID live process-group CPU/RSS, parent counters, available filesystem/RAM headroom and a narrow projection of the source's existing RPC/native/WATCH/evidence counters. Source snapshot time remains distinct from resource observation time. A stable PID/start-time membership is required for interval CPU; missing processes, membership changes and counter regressions produce unknown values rather than fabricated zero usage. CPU fractions refer to one core and may exceed one for multiple threads; live-group CPU omits already exited child processes. Summed RSS does not deduplicate shared pages. The filesystem free-space figure is host headroom, not proof that POE alone consumed the difference. Source-reported byte counters retain their original measured/accounted/uncertain meanings; they are not relabeled exact disk or wire measurements.

The file is capped at 256 KiB per segment, with at most two existing segments. Telemetry failure or capacity exhaustion disables only this diagnostic and records the reason; it does not stop financial management. No final census/file-read/hash pass is added before retained-exposure recovery. The summary uses an incremental hash. Samples are ordinary writes without separate fsync, so a crash may leave incomplete diagnostic evidence; no crash-durability or continuous-resource claim follows. The reader allows legacy runs without this file, but requires exact hashes, identities, time bounds and an explicit schema for new nonempty files. It exports neither command lines/environment values nor raw financial records. It also preserves the consolidated scheduler's new bounded service/phase/origin metadata and genuine Undici pre-write dispatch-hook timing/socket-identity fields (not successful socket writes or provider receipt) in existing observation evidence.
