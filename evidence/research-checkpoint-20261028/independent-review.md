Two findings were sent to the implementation agent and lead:

1. Missing physical timestamps were initially shifted to `book.lastObservedAt`. That is not an upper bound: ComponentBudget invokes transport before persisting its actual timestamp, so a crash can retain only the earlier reservation time. Unknown timestamps must use independently verified settlement/seal time conservatively, with no assertion that this is actual provider timing. Prior checkpoint estimates must age at their original fixed values. The corrected implementation now uses seal time for unknown stamps, records conservativeUnknownAtSeal, and retains prior-anchor estimates without retiming. A dedicated old-book/crash-window regression covers this case.
2. The public-input exporter still compares the current manifest path list with the original settled raw path list. Adoption of a valid checkpoint necessarily changes that list and initially could not pass the next handoff. A verified compacted-handoff relation is required; the old guard must not simply disappear. The implementation now provides verifyResearchCheckpointSourceHandoff, which independently checks the pinned seal against exactly the original ordered source records/hashes, cumulative calls/bytes, uncertainty, pending count and historical refusal. Root exporter guards remain unchanged; adopting this helper into the actual export/adoption path is still a lead integration obligation.
