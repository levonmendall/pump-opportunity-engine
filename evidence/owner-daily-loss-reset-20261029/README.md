Base source `8410390e31e1248f584406f27030b3e0e2cf4484`. Owned change: `PaperLedger.resetDailyLoss(id, now, price, marks, reason)` plus focused offline tests. No operating database, EC2 service, provider or authoritative financial state was accessed by this task.

The method uses the existing sole financial writer's `apply` transaction, `actions` receipt and `journal` event `owner-daily-loss-reset`. It requires an existing same-day loss latch, flat/no-pending accounting, empty marks, reconciliation no older than two seconds and valid USD no older than ten seconds. It records previous daily state, observed conversion, current actual equity, replacement risk baseline, account/inception, revision and time in its durable receipt. Only the daily risk reference and loss flag change; cash, capital, trading P&L, orders, original history and every entry control remain intact. `daily.paused` remains true; no entry is armed.

Authorization identity is the stable action id plus reason. Same id/reason returns the ORIGINAL receipt even when a retry observes a later time/price/loss; it does not waive the later loss. A changed reason conflicts. The usual $50 daily-loss check remains enabled and relatches on a new loss. This is not a permanent risk-policy change or financial-account restart.

The existing authenticated runtime callback must bind the explicit owner request to its fixed id and check physical uncertainty/idle/financial/evidence/owner/hard-stop safety. Those conditions are outside the ledger's persisted flat-state knowledge. If raw entry controls are still enabled, the callback must use the existing temporary readiness pause before reset and recover only through normal genuinely fresh audited readiness. This ledger method never clears an owner stop or grants that recovery itself.
