# HTTP/control cooldown containment and recoverable transport integrity

This change repairs the local failure coupling demonstrated by the exact source-640 target prefix: four HTTP audit cooldowns caused all six native candidates to be retired and their shared WebSocket to be closed, accounting for 24 of 36 gap callbacks. It does not reinterpret those historical interruptions as complete coverage, change the strategy, weaken event/audit requirements, or claim remote provider saturation.

## Changes

* `PilotRpc` applies HTTP and control cooldowns to their own admission domains. Every domain still uses the same physical operation gate, pacing, cumulative requests/bytes, immutable failed chapters, unresolved reservations, storage/fatal checks and actual-settlement guards. Successful controls do not clear an HTTP Retry-After, and successful HTTP does not clear a control Retry-After. No automatic retry or provider identity change is introduced.
* `rpcDispatchWindow` and `controlDispatchWindow` expose domain readiness. The legacy `dispatchWindow` remains conservative across both cooldowns. Cooldown accessors preserve remaining monotonic delay rather than relying only on the wall clock.
* Native flow plans support work and control work independently, including a known external HTTP cooldown before the first refused support call. A cooldown admission refusal preserves valid ongoing capture, remembers the domain's retry time and starts no hidden request. An expiry race remains a refusal, not a reason to tear down capture. Actual 30-second support/source validity remains unchanged and still invalidates admission when expired.
* An owed pong remains queued until a successfully settled control operation. Its original three-second liveness deadline remains enforced locally even while control admission is unavailable; expiry closes the transport recoverably without sending an unadmitted frame.
* The later source-640 `NATIVE_FLOW_UNSCOPED_NOTIFICATION` stop lacked enough context to distinguish a new unknown ID, expired retirement metadata or an early-notification queue overflow. New bounded diagnostics record only numeric IDs, counts, connection/generation state, ACK method/ID and retirement timing. They never retain raw unknown payloads, transaction signatures or logs.
* A well-formed unscoped notification or bounded early-queue overflow admits no unknown information, invalidates the affected generation and closes the transport. Actual close settlement, existing increasing reconnect backoff, fresh support/ACK and a complete new window are required. A CLOSING socket cannot start controls or another connection. Repeated incidents retain increasing backoff. Malformed messages and accounting/storage/resource failures remain hard refusals. Neither the eight-item early queue nor the retirement TTL was enlarged.

## Validation and limits

The focused RPC/native-flow tests reproduce six-candidate cooldown containment, continued valid capture, first-turn simultaneous support/heartbeat demand, exact cooldown-expiry refusal, true support expiry, independent Retry-After domains, mixed 60/minute and short-window pacing, unsettled operations blocking both domains, bounded unknown-ID diagnostics, malformed-ID hard refusal, actual-close-before-reconnect, fresh-window rebuilding and increasing backoff. Original tests for corrections, retirement, overload retention, raw evidence and source timing remain included.

Raw output and exact four-file hashes are in `focused-tests-final.log` and `focused-tests-final-receipt.json`; type checking is in `build-final.log` and its receipt. Earlier intermediate verification is retained separately. Independent source review identified and prompted correction of first-turn control starvation, cooldown-expiry race and a newly permanent liveness failure before handoff.

This is offline verification. It does not demonstrate provider entitlement, future HTTP completion latency, six-busy-pool audit capacity, holding protection, financial execution or forward recovery. The original unscoped notification's precise cause remains unproven without older raw context. A new versioned forward interval must verify that the coupled teardown disappears under actual HTTP degradation and that repeated integrity failures remain recoverable without claiming uninterrupted coverage.

No provider requests, financial writes, installation, deployment or commit were performed by this implementation worker. The lead owns final review, complete regression verification, release identity and deployment.
